# Revo UI

UI components for financial apps, reporting dashboards, and project management. Build with React, Vue, Angular, Svelte, Preact, or vanilla TypeScript.

This repository owns the `@revolist/ui` library and its gallery demo: interactive examples, component variants with formatted usage code, and framework integration guides.

## Development

This repository is consumed as the `packages/ui` submodule in the RevoGrid Pro workspace. Component implementation and colocated unit tests live in `package/`; the gallery demo lives in `src/`, and all standalone browser specs and fixtures live in `tests/browser/`. The root Playwright configurations work from this repository alone.

From the parent workspace:

```sh
git submodule update --init packages/ui
pnpm install
pnpm dev:ui
```

```sh
pnpm --filter @revolist/ui lint
pnpm --filter @revolist/ui build:demo
pnpm --filter @revolist/ui test:browser
```

From this repository root, use `pnpm dev` for the gallery, `pnpm build` for the library, and `pnpm build:demo` to prerender the gallery. A standalone clone is self-contained; install with `pnpm install --frozen-lockfile`.

## Component API reference

The gallery header and API reference display the version read from the current `@revolist/ui/package.json` at build time.

Each component family includes an always-visible API reference, with an expandable entry for every catalog component. Items use the shared `Disclosure` component, with Font Awesome SVG chevrons indicating the disclosure state. A compact API reference shortcut in the page introduction links directly to the family’s API section. Props and events/callbacks show their TypeScript signatures, required status and source comments. Inherited HTML attributes and events are available in a nested disclosure. Methods list public controller methods reachable through a component prop or callback; components without imperative methods say so explicitly.

The reference is generated by `scripts/component-api.mjs` from the current library's `component-catalog.ts` and component declarations during Vite loading. Shared native declarations are deduplicated, and the reference loads when its component family mounts. Changes to source declarations are watched during development. Add family assignments in `docs/component-groups.json` when introducing a catalog component. Run `pnpm --filter @revolist/ui test:api` to verify extraction and catalog coverage. Underlined complex types expand into their resolved union values, object fields, array items, index signatures, and callback parameters/results. The extractor keeps a shared graph to handle recursive types without a depth cutoff. `scripts/api-descriptions.mjs` supplies source-checked editorial descriptions when the library declaration has no JSDoc; the API contract tests require descriptions for every library-declared prop and callback.

## Integration

Import shared components through `@revolist/ui` exports and load `@revolist/ui/styles.css` once. The Frameworks section explains each adapter's setup, state, events, and lifecycle.

## GitHub Pages

The gallery is deployed independently from demos: [Open Revo UI](https://ui.rv-grid.com/).

`.github/workflows/pages.yml` builds and deploys on pushes to `main` and manual dispatch. It checks out the exact library commit recorded in `library-source.json`, prepares an isolated UI/dates/chart-utils workspace, installs `pages.pnpm-lock.yaml` with `--frozen-lockfile`, typechecks, and builds with the `/` asset base for `ui.rv-grid.com`. Only the static `dist` output is uploaded to Pages.

The workflow uses `REVO_UI_LIBRARY_READ_KEY`, a read-only deploy key for the private library repository. It does not publish that repository's source tree. To update the component version, change `library-source.json` to a published source commit and regenerate the Pages lockfile if dependency manifests changed.

The demos Docker image no longer builds or serves Revo UI.

Revo UI is MIT licensed and may be used in commercial projects. See [LICENSE](../LICENSE).

The custom domain requires a DNS CNAME record: `ui.rv-grid.com` → `revolist.github.io`. Use DNS-only mode until GitHub validates DNS and provisions HTTPS.

## SEO and static rendering

The production build pre-renders the overview, component directory, all component families, colors, and framework guides into separate HTML files. Routes such as `/components/buttons/` and `/frameworks/react/` work on direct visits to GitHub Pages. Each page has its own title, description, canonical URL, and social URL. Navigation and the generated `sitemap.xml` share `src/pages.json`; `robots.txt` references the sitemap. Existing hash and `?page=` links redirect in the browser to their canonical paths; hashes remain available for sections and individual examples.

The build verifies every generated page with `scripts/check-pages.mjs` and emits the RevoGrid favicon, touch icon, and PNG social preview. `node scripts/seo.test.mjs dist` checks the homepage and shared SEO assets. The build requires Chromium (`pnpm exec playwright install chromium` locally); the Pages workflow installs it automatically.

## Browser suites

- `pnpm test:browser`: standalone component and gallery behavior.
- `pnpm test:frameworks`: React, Vue, Angular and Svelte adapter contracts.
- `pnpm test:tooltips`: clipping, placement and tooltip lifecycle.
- `pnpm test:fields-styles`: native field styling and focus states.
- `pnpm test:pdf-viewer` and `pnpm test:pdf-frameworks`: explicit PDF suites.
- `pnpm test:visual-audit`: explicit exhaustive screenshot capture.
- `pnpm test:discovery`: verify suite ownership and discovery.

All specs and fixtures live in `tests/browser/`. Product-feedback tests that depend on private products remain in the parent monorepo.
