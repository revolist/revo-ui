# Tooltips

Tooltips add short, non-interactive descriptions to a focusable trigger. Revo UI shares one tooltip engine across Preact, React, Vue, Angular, Svelte, vanilla JavaScript, and the browser/CDN build. It handles ownership, timing, keyboard dismissal, placement, and cleanup consistently.

[Try the live examples](https://ui.rv-grid.com/components/tooltip/) · [Tooltip props](api/Tooltip.md) · [Controlled surface props](api/ControlTooltip.md)

## Basic and rich content

```tsx
import { Tooltip } from '@revolist/ui/react'; // or /preact

<Tooltip text="Exports the visible rows" side="bottom" arrow>
  <button>Export</button>
</Tooltip>

<Tooltip content={<><strong>CSV export</strong><span>Includes column names.</span></>}>
  <button>Export details</button>
</Tooltip>
```

The first button, input, textarea, select, link, summary, editable element, or element with a tabindex is the trigger. An explicit `anchor` can reference an external HTML or SVG element. `text` remains the simple fallback; `content` supplies rich descriptions; `renderContent({ target, reason, event })` renders per-target content. Strings are text, never automatically interpreted as HTML.

React content and render callbacks use React nodes; Preact uses Preact nodes. In Vue use the default slot for the trigger and the `content` slot for its description. Angular uses `rvUiSlot="default"` and `rvUiSlot="content"`; Svelte uses children and `slots={{ content: descriptionSnippet }}`. Content slot scope includes `context` (target, reason, event). Use the corresponding framework adapter, rather than passing one framework's VNodes to another.

## Placement and presentation

| Options | Behavior |
| --- | --- |
| `side` | `top` (default), `bottom`, `left`, `right`, `inline-start`, `inline-end`. Logical sides follow computed direction or explicit `direction`. Legacy `placement="above"` remains supported. |
| `align` | `start`, `center` (default), `end`; horizontal alignment follows RTL direction. |
| `sideOffset`, `alignOffset` | Pixels, or functions receiving `{ anchor, popup, side, align }`. Defaults: 8 and 0. |
| `collisionBoundary` | An element or viewport-coordinate DOMRect, intersected with the viewport. Defaults to the viewport. |
| `collisionPadding` | A number or per-edge object; default 8px per unspecified edge. |
| `collisionAvoidance` | Default flip and shift. `false` disables both; `{ side: 'none', align: 'shift' }` and `{ side: 'flip', align: 'none' }` control them separately. Oversized content is constrained while avoidance is enabled. |
| `sticky` | Keeps following a scrolled trigger; default hides a hover hint on ancestor scroll. Keyboard-focused hints follow their trigger while it stays on screen. |
| `arrow` | Shows a decorative arrow pointing toward the anchor. Default false. |
| `width`, `height`, `maxWidth`, `maxHeight` | Pixel numbers or CSS lengths. Default maximum width is 360px with viewport constraints. Oversized content scrolls. |
| `className`, `style` | Additional classes and inline styles. Theme with `--rv-tooltip-bg` and `--rv-tooltip-fg`; keep sufficient contrast. |
| `appendTo` | HTMLElement or ShadowRoot portal destination. Detached surfaces otherwise mount in the trigger document's body. Native popovers promote them above clipping containers. |
| `keepMounted` | Retains the hidden surface after it has opened. Destruction always releases owned surfaces. |
| `transitionDuration` | Optional opacity transition in milliseconds; default 0. Respects system reduced motion and shared UI motion settings. |
| `id` | Optional stable description ID; generated by default. Keep it unique within the document and stable while open. |

Surfaces expose `data-side`, `data-align`, `data-state` (`opening`, `open`, `closing`, `closed`), and `data-visible`. Positioning publishes pixel CSS variables `--anchor-width`, `--anchor-height`, `--available-width`, `--available-height`, `--rv-tooltip-arrow-x`, and `--rv-tooltip-arrow-y`. Positioning uses fixed viewport coordinates. Ancestor scroll, viewport resizing, and anchor/content resizing update or dismiss the popup according to its mode.

## Triggers, delays, and shared groups

Default `trigger="hover"` supports both pointer hover and keyboard focus. `focus`, `click`, and `manual` select a single mode; an array such as `['focus', 'click']` selects explicit modes. Click triggers use native clicks, including a button's Enter/Space activation. Touch does not emulate hover. `disabled` suppresses the hint without disabling the host button.

| Option | Default and purpose |
| --- | --- |
| `delay` | 0ms hover delay; overrides the group delay when supplied. |
| `focusDelay` | 0ms; keyboard focus remains immediate unless explicitly configured. |
| `closeDelay` | 0ms pointer-exit delay, or the group's close delay. |
| `autoHide` | true; false keeps the hint after pointer exit. Blur, Escape, outside presses, and owner cleanup remain separate dismissal paths. |
| `disableHoverablePopup` | false; the user can cross the trigger-to-popup gap and hover its description. |
| `hideOnClick` | true; ordinary hints dismiss on trigger activation. Click-triggered hints toggle instead. |
| `closeOnEscape`, `closeOnOutside` | true; independently control Escape and outside-pointer dismissal. |

```tsx
import { Tooltip, createTooltipGroup } from '@revolist/ui/react';

// Keep one stable group object for these controls, e.g. with useState/useMemo.
const group = createTooltipGroup({ delay: 600, closeDelay: 100, skipDelayDuration: 400 });

<Tooltip group={group} text="First description"><button>First</button></Tooltip>
<Tooltip group={group} text="Second description"><button>Second</button></Tooltip>
```

A group defaults to 600ms initial hover delay and a 400ms warm window. Nearby hints open immediately while a group member is open or the warm window has not expired. Explicitly sharing a group object also works between separate framework roots. Only one shared tooltip is visible per document; opening another replaces the previous owner. Destroy controls when their view is removed.

## Controlled state and lifecycle callbacks

```tsx
const [open, setOpen] = useState(false);
<Tooltip text="Review changes" open={open}
  onOpenChange={(next, details) => setOpen(next)}>
  <button>Review</button>
</Tooltip>
```

Omit `open` for internal state; `defaultOpen` opens initially. With `open`, interaction requests notify the application and wait for its supplied value. `onBeforeOpenChange(next, details)` can return false to cancel an interaction request. State synchronization itself does not emit a duplicate request. Disabling, destruction, disconnected/offscreen anchors, and ownership replacement force cleanup, including for controlled tooltips; synchronize application state using the callbacks where relevant.

| Callback | When it runs |
| --- | --- |
| `onBeforeOpenChange(next, details)` | Before an interaction/imperative request; false cancels it. Forced cleanup bypasses cancellation. |
| `onOpenChange(next, details)` | Requests a state change. |
| `onShow(details)`, `onHide(details)` | Actual logical opening/closing. Destruction silently cleans up. |
| `onOpenChangeComplete(next, details)` | After the corresponding transition, or immediately without motion. Interrupted transitions do not complete. |
| `onEscape()` | An active/pending tooltip handles Escape. |
| `onContentLoad(text, details)`, `onError(error, details)` | The current asynchronous load succeeds/fails. |

Details include `target`, optional native `event`, and a `reason`: `hover`, `focus`, `click`, `imperative`, `controlled`, `escape`, `outside-press`, `pointer-leave`, `blur`, `press`, `disabled`, `owner-change`, `anchor-removed`, `viewport`, or `destroy`. Cleanup removes only the tooltip's own `aria-describedby` token, preserving the host's other descriptions.

## Asynchronous content

```tsx
<Tooltip text="Report details" loadingContent="Loading details…"
  errorContent="Details unavailable. Try again."
  loadContent={async ({ target, signal }) => {
    const response = await fetch(`/api/reports/${target.dataset.reportId}`, { signal });
    if (!response.ok) throw new Error('Report request failed');
    return (await response.json()).description;
  }}>
  <button data-report-id="quarterly">Report information</button>
</Tooltip>
```

`loadContent` returns a Promise of text. It runs when the tooltip opens and on controller `refresh()`. The AbortSignal is canceled on closing, changing targets, refreshing, or destroying the controller. Stale results and errors are ignored. Loading sets `aria-busy`; successful/error results survive parent rerenders. Without `errorContent`, an unsuccessful load closes the hint. Provide translated loading/error content and use the host application's data layer for caching, authentication, request-start instrumentation, and retries. Changing a loader callback does not implicitly restart an in-flight load; call `refresh()` to reload. Removing `loadContent` aborts the pending request and restores local content immediately.

## Vanilla JavaScript, delegation, and imperative methods

```js
import { TooltipController } from '@revolist/ui';
// Without a bundler, import from the versioned browser/revo-ui.js CDN build.

const hints = new TooltipController();
hints.bind(document.querySelector('#toolbar'), '', {
  filter: '[data-help]',
  renderContent: ({ target }) => target.dataset.help,
  side: 'bottom', arrow: true,
});
// One binding also covers matching buttons added later.
hints.show(document.querySelector('[data-help]'));
// On view teardown:
hints.destroy();
```

| Member | Purpose |
| --- | --- |
| `bind(anchor, content, options?)` | Replaces the binding and returns a disposal callback. With `filter`, the anchor is a delegation container. |
| `show(target?)`, `hide()`, `toggle(target?)` | Immediate imperative requests; supplied controlled state still authorizes visibility. Pass an actual matching trigger when showing a delegated tooltip. |
| `setOpen(open, target?)` | Synchronizes externally owned visibility without another request callback. |
| `target()` | Current/most recently active trigger. |
| `isOpen`, `element` | Logical visibility and the presentation element. |
| `setContent(content)` | Updates base text, DOM node, or Preact content. |
| `update(options)` | Replaces configuration, updates open presentation, and preserves the binding. Rebind when changing `filter`. |
| `refresh()` | Repositions and reloads/rerenders current content. |
| `destroy()` | Aborts requests, removes listeners/timers/ARIA, and disposes the owned surface. |

Preact `useTooltip(text, floating?, options?)` exposes `triggerProps`, `tooltip`, `show()`, `hide()`, and `refresh()`. Spread its trigger props onto a native focusable element and render its tooltip once. Existing host refs are preserved; an optional anchor references an external trigger. Compose any event handler you override, including onClickCapture. Its presentation options include rich Preact `content`, controlled `open`, and `defaultOpen`; asynchronous/delegated rendering belongs to `Tooltip` or `TooltipController`. `ControlTooltip` is a presentation adapter with required `id`, `text`, `visible`, and an optional external `anchor`.

## Accessibility and scope

Keep essential instructions visible. Give icon-only triggers an accessible name, and use a real button for focus access. Tooltips describe their triggers using `role="tooltip"` and `aria-describedby`; they do not move focus. Hover hints remain readable while crossing to and hovering the popup. Escape dismisses the active tooltip before its parent popup handles Escape. Reduced motion and forced colors are supported by the shared surface.

Rich content should remain descriptive. Links, forms, interactive widgets, and embedded documents need a Popover or Dialog with an appropriate focus model. The tooltip does not inject arbitrary remote HTML or embed iframes. Fullscreen/top-layer behavior and assistive-technology results still depend on the host application and browser. See [accessibility guidance and verification limits](https://ui.rv-grid.com/accessibility/).

The API review used [Base UI Tooltip](https://base-ui.com/react/components/tooltip#api-reference) and [Kendo Tooltip](https://www.telerik.com/kendo-jquery-ui/documentation/api/ui/tooltip) as capability references. Revo UI provides the core state, placement, timing, content, delegation, and lifecycle capabilities through its existing cross-framework API; it does not duplicate those libraries' component anatomy or option names.
