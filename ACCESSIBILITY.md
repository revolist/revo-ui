# Shared UI accessibility

Reviewed 10 November 2026 against [WCAG 2.2 Level A and AA](https://www.w3.org/TR/WCAG22/). The scope is the shared UI source and the default standalone gallery, including the representative states listed below. This is an engineering coverage record, **not a declaration of full WCAG conformance or a certification**. Conformance applies to complete pages and processes, including application content, integration and accessibility-supported use.

## Coverage and reproducible checks

Run commands from the workspace root:

```sh
pnpm --filter @revolist/ui test
pnpm --filter @revolist/ui lint
pnpm --filter @revolist/ui test:browser
pnpm --filter @revolist/ui exec playwright test --config playwright.tooltip.config.ts
pnpm --filter @revolist/ui exec playwright test --config playwright.pdf.config.ts
pnpm --filter @revolist/ui test:frameworks
pnpm --filter @revolist/ui test:pdf-frameworks
```

The ordinary gallery runner builds its own gallery. `UI_SKIP_BUILD=1` skips that build only when an up-to-date local gallery is already served. Browser fixtures and PDF/framework checks have separate owners; an ordinary gallery run does not imply they passed.

- `tests/browser/accessibility.spec.ts` scans the **full component specimens** at `/#components` (PDF excluded), rather than the overview at `/`, and the Colors page in light/dark themes at 1280px and 390px. Axe runs the WCAG A/AA tags through 2.2 and attaches its complete results. A zero-violation result does not convert `incomplete` findings into passes.
- Additional scans exercise an open dialog, its nested dropdown, a nested confirmation, an empty remote lookup, its editor after dismissal, and invalid calendar range feedback in both themes. Base surfaces are scanned separately from their nested popups; nested dropdown scans target the active popup rather than controls underneath it.
- Keyboard focus is checked with forced colors and reduced motion. The gallery header is checked at 320 CSS pixels, and full specimens are checked for page-level reflow with increased line/paragraph/letter/word spacing. These checks do not establish that all text remains readable in every custom composition.
- `accessibility-interactions.spec.ts` uses actual taps at 320px and 1280px for all timeline move/resize commands and field reordering. Existing suites cover calendar, tabs/radios, menus, dialog focus, Escape, focus return, resizing, RTL, editing and responsive layouts.
- `tooltip.spec.ts` covers clipping, shared presentation, slow travel across the anchor-to-tooltip gap, hovering the tooltip, persistence, Escape dismissal and pointer exit. The shared owner also serves declarative, title and delegated selection-list hints.
- PDF behavior and automated viewer/mobile-tools scans live in `pdf-viewer.spec.ts`; the document text layer and the host-provided PDF's accessibility require separate review.

## Changes closing documented engineering gaps

| Concern                           | Resolution                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hover content (1.4.13)            | Shared tooltip surfaces accept pointer hover. The session preserves travel across the gap without a hide timeout and dismisses on exit or Escape. SvgButton forwards the pointer coordinates; delegated list hints use the same lifecycle. Existing focus, description and teardown tests remain applicable.                                                                                                                                                                                                                                                                                                        |
| Drag alternatives (2.5.7)         | `TimelineTrack` provides a native **Edit timeline events** disclosure with click/tap commands for moving and changing either endpoint, including zero-length events. The labels are overridable through `labels`; commands use the same controlled model, bounds and step as drag/keyboard interactions. `showActions` defaults to true. A host setting it to false must provide an equivalent alternative. The field gallery exposes up/down actions through `useFieldReorder.move`, and the resizable-panel example supplies a native numeric stepper; product adapters must expose their own equivalent actions. |
| Narrow timeline targets (2.5.8)   | Event affordances reserve room for the central move action between edge handles, and events use separate visual lanes to prevent overlapping controls. The visual minimum is an interaction affordance; exact event values remain available in the action disclosure. Arbitrarily dense/overlapping event layouts still require host review and the separate commands.                                                                                                                                                                                                                                              |
| Dropdown semantics (1.3.1, 4.1.2) | The options list owns the listbox role; its search field, status and auxiliary buttons are siblings rather than invalid listbox children. Private popup ownership keeps the portalled search and auxiliary controls linked to their editor. Open nested-dropdown scans cover the actual rendered state. Collapsed controls omit references to unmounted listboxes.                                                                                                                                                                                                                                                  |
| Spacing/reflow (1.4.10, 1.4.12)   | Narrow gallery navigation wraps and long output values can break across lines with increased text spacing. Two-dimensional content, such as the weekly time grid, retains a local scroll surface.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Existing contracts                | Native names and localized label hooks, selected/disabled states, status/error feedback, semantic accent text, avatar text contrast, 24px compact actions, and visible focus outlines remain covered by their owner and browser tests. Data palettes are not changed to manufacture accessibility results.                                                                                                                                                                                                                                                                                                          |

Named count/configuration badges now expose a named graphic role instead of placing `aria-label` on a generic span. Reviewing axe's incomplete results also identified closed-popup references; those are now absent while collapsed. Remaining incomplete categories include contrast over pseudo-elements/gradients and ambiguous label/name relationships. They require visual or assistive-technology review rather than suppression. Pagination gap markers are decorative, and the two palette groups have an explicit grouping role.

Incomplete-result triage is retained in the report:

| Finding                       | Interpretation and next verification                                                                                                                                                                                                                              |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aria-input-field-name`       | Check that a nearby visible label belongs in the accessible name, particularly when a host explicitly overrides the name. Verify with speech input and a screen reader.                                                                                           |
| `aria-valid-attr-value`       | Date, color and submenu triggers may retain stable popup IDs while collapsed. Review their relationships in the opened state; the nested menu/calendar suites cover dismissal and focus return. This does not count as an automated pass for an unmounted target. |
| `aria-required-children`      | An empty remote lookup deliberately contains no selectable option. Its no-results status is outside the listbox. Review the empty-state announcement with a screen reader; do not manufacture a fake choice just to silence this finding.                         |
| `color-contrast`              | Pseudo-elements, gradients and non-text symbols prevent a reliable automated measurement. Visually measure the actual foreground/background paints and all relevant states.                                                                                       |
| `label-content-name-mismatch` | Check icon-only links, labels and abbreviations against their displayed content and supported speech commands.                                                                                                                                                    |

For a durable audit report, run the accessibility spec with `--reporter=list,json` and set `PLAYWRIGHT_JSON_OUTPUT_FILE` to a local output path. The JSON report retains the complete axe response bodies, including incomplete findings, in its test attachments.

## Required manual validation before claiming conformance

The engineering fixes above do **not** erase these validation requirements. No VoiceOver or NVDA session has been performed in this review, and automated axe results do not cover every WCAG criterion.

Record browser/OS/screen-reader versions, input method, route, theme, viewport/zoom, steps, expected result, actual result and failures for each task:

1. **VoiceOver + Safari and NVDA + Firefox or Chrome:** traverse the gallery, choose a component through navigation/search, edit fields and recover from errors, operate a calendar/range, select and remove resources, search an empty/failed lookup, move a field, move/resize a timeline event, open nested overlays, dismiss each layer and verify focus return. Check names, roles, state/value, reading sequence, live messages and absence of traps. Include the PDF viewer with an accessible tagged PDF.
2. **Zoom, text and focus:** test 200% text-only enlargement, 400% browser zoom, the WCAG spacing overrides, long translations and RTL. Inspect each control and open overlay for clipped text, lost controls and obscured focus. Check the documented two-dimensional-content exceptions rather than hiding overflow to pass a page-width assertion.
3. **Contrast and platform settings:** inspect axe `incomplete` results and every relevant foreground/background/state combination, including SVG/canvas/gradients, custom colors, native high contrast, forced colors and reduced motion. Browser emulation is evidence, not a report that an OS setting or assistive technology was used.
4. **Pointer/touch and application processes:** validate target spacing, very short/overlapping timeline events, cancellation and no-drag alternatives, then complete the application's actual submit/authentication/session/help flows. Recheck custom renderers, PDFs and themes supplied by the host.

The consuming application owns its custom content, localized names, domain validation, focus order, complete workflows and integration-specific gesture alternatives. Keep icons decorative when their control already supplies the accessible name. Re-run the affected checks when these inputs or the library change.

## Validation for this revision

The red-before-green checks reproduced tooltip dismissal during pointer travel, the absence of timeline tap actions, narrow timeline target-size violations, invalid nested listbox ancestry and page overflow under increased text spacing. Recorded results for this revision:

- All 746 UI unit tests passed; UI TypeScript lint and `git diff --check` passed.
- All nine production accessibility cases passed: 20 axe scans reported zero violations. The five remaining incomplete categories are triaged above and are not passes.
- All 21 production regression checks passed, including tap alternatives, drag/insertion feedback, narrow spacing, date/time layouts and pre-rendered page checks. The broader source-gallery run exercised 215 cases with 209 passes; all six failures passed on the production recheck. A new complete 215-case production run was not performed.
- All seven tooltip browser cases passed. The dedicated production PDF automated accessibility case passed in light and dark themes.
- The framework/adapter run passed 21 of 22 cases; its Vue case passed on focused recheck after its locator distinguished the labeled trigger from the labeled listbox.
- The production gallery build verified 221 static pages, titles, canonicals and navigation.

No screen-reader session, text-only zoom assessment, full custom-paint contrast review or full product/application conformance audit is represented by these results.
